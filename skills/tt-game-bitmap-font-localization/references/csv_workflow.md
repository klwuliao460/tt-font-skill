# TEXT.CSV 改写 + 繁简转换 + 双语字幕决策树

## 1. 文件格式（写回必须一模一样）

- 全字段加引号、**LF**、UTF-8 **无 BOM**
- 写回：`csv.writer(f, quoting=csv.QUOTE_ALL, lineterminator='\n')`，读入用 `encoding='utf-8-sig'`
  （兼容个别带 BOM 的副本），写出后 `font` 侧脚本会校验 BOM/CR
- 列（LMSH2，20 列）：`LABEL, PLATFORM, TYPE, ENGLISH(3), AMERICAN, FRENCH, GERMAN, SPANISH,
  ITALIAN, DANISH, JAPANESE, RUSSIAN, POLISH, FRENCH CANADIAN, BR PORTUGUESE, DUTCH, KOREAN,
  MEXICAN, CHINESE TRADITIONAL(18), ARABIC(19)`
- 中文字段名可能不同（其他 TT 游戏用 `CHINESE SIMPLIFIED` 等）→ **一律按表头名取列**，别写死索引
- `¬` 是"此语言无文本"的占位符，**必须跳过**
- `~7…~~` 是颜色标记（如 `~7關普：~~`），改写必须**原样保留**，宽度估算按字符数照算

## 2. 可改行范围（LMSH2 实测）

- 字幕 = `TYPE ∈ {Subtitle, Dialogue}` → **10544 行**可改（总行 14622）
- 按 TYPE 的候选行数：Subtitle 10194 / Game 2304 / LegoAPI 480 / Char 438 / Dialogue 350 /
  Framework 229 / TRC 147 / Marketing 102 / Hint 80 / Ach_Desc 79
- **面板类文本（Game/Char/Hint…）不是字幕**：它们支持多行同时显示，不要塞英文尾巴

## 3. 繁简转换：两层，别混

**第一层 · 逐字（字体侧，文本不动）**

- `OpenCC('t2s')` 对部署文本里出现过的繁体字生成"繁体码位 → 简体显示字形"替换对
- 效果：繁体码位的**槽位画简体字形**，CSV 文本码位不变 → 零闪退风险
- 只对 `0x4E00–0x9FFF` 且 `len(结果)==1 且 != 原字` 的条目替换
- 繁体码位不在字体字符表 = **缺字**（LMSH2 实测 14 个：臺覈喫纔巖釐峯詠捱牀侷羣），
  只能改文本或接受，**不能加槽位**

**第二层 · 上下文相关字（文本侧）**

- 著 / 瞭 / 藉 / 乾 这类一字多义，`t2s` 保守不转（著名、顯著、瞭望、慰藉 必须保留原字）
- 用 `OpenCC('tw2sp')` 做**短语判定**，只把判定该转的那一个白名单字替换进原文，其余一律不动
  （`tw2sp` 顺带改到的非白名单差异要**忽略** —— LMSH2 全表 4628 处）
- 白名单：`{著:着, 瞭:了, 藉:借, 乾:干}`
- **转换目标字必须存在于字体字符表**（`csv_trad_fix.py --font` 会校验，缺槽位直接 FAIL）
- LMSH2 实测：全表 400 行 / 420 处（著→着 298、瞭→了 74、藉→借 17、乾→干 31），
  另有 14 处判定保留（著名 / 顯著 / 瞭望 / 慰藉 等）
- 注意：2026-10-31 那版成品只对 Subtitle/Dialogue 做了这层，`TYPE=Game/Hint/Framework` 里
  还剩 88 行带 著/瞭 → `csv_trad_fix.py` **默认全行修正**（更彻底）；要逐字节复现旧成品就加
  `--types Subtitle,Dialogue`

## 4. 双语字幕决策树（按序排除，别重走死路）

1. **`\n` 求双行同时显示** → 字幕元素是**单行分页**，变成轮播，没有电影感
   （只有面板类文本才多行同时）→ 不满足"同时可见"就往下走
2. **新槽位半号拉丁** → 插入式被 exe 硬编码偏移堵死；原地回收槽虽可用，但文本里出现
   私用区 / 生僻码位（`U+FF61`、`U+9FE0` 实测）**启动期闪退** → **整条死路**
3. **最终形态 = 宽度预算分流（`csv_bilingual.py`）**
   - `36*len(全角) + 22*len(半角) <= 1180` → 同行 `中文␣英文`（两行同时可见）
   - 否则 → `中文\n英文` 干净轮播
   - 中文基底本身含 `\n`（面板/多行文本）→ 强制轮播
   - 英文取 `ENGLISH` 列**原始大小写**，不转大小写、不缩号
4. **内联全尺寸英文的长行**会被引擎在英文中间切断分页（页1 = 中文 + 英文头部）→ **必须走分流**

## 5. 分流规则的重现度（2026-11-05 实测）

- 对部署成品跑 `csv_bilingual.py --check`：**10469/10544 行（99.3%）与规则一致**
- 边界很硬：同行行 est `max=1180`，轮播行 est `min=1182`
- 75 行差异全部落在预算边界带 —— 因为 36/22 是**常量估算**，真实字宽按 rect 累加会有出入
  （`I . ' -` 远窄于 22px，`W M` 更宽）
- 判断标准不是"逐字节复现旧成品"，而是**进游戏看有没有"英文被从中间分页"**：
  有 → 收紧 `--budget`；短字幕被无谓拆成轮播 → 放宽
- 要更贴真实宽度：可用坐标表 `rect.w` 逐字累加替代 36/22 常量（未实现，属可选优化）

## 6. 校验清单（每次改 CSV 后、部署前）

- [ ] 除目标列外**零差异**
- [ ] 无 BOM、无 CR
- [ ] 抽样打印同行 / 轮播各几条，人眼确认颜色标记与标点没被吞
- [ ] `¬` 占位行没被动
