# FT2（TNFN 位图字体图集）二进制结构速查

> 数字与偏移全部来自 2026-10-31《乐高漫威超级英雄2》`FONT_CH_NXG.FT2` 实测；换游戏时先用
> `scripts/font_probe.py` 打印结构（偏移由公式自洽推出，不必假定同一常量）。
> 一切结论以 `font_probe.py` 的输出为准，不要靠猜偏移。

## 1. 布局总览（LMSH2 实测）

| 区段 | 偏移 | 内容 |
|---|---|---|
| 文件头 | `0x00`..`0x3F`（64B，大端） | 见 §2 |
| 坐标表 rect table | `0x4F` | 3107 条 × 28B |
| （间隙） | 坐标表后 8B | 定长填充，字符表起点公式里的 `+8` |
| 字符表 char table | `0x1542B` | 3108 条 × 4B |
| DDS 图集 | `0x184CF` | 128B DDS 头 + DXT5(BC3) 块，2032×3652 |

文件总长 7520527 字节。图集块网格 508×913（每块 16B）。

## 2. 文件头字段（大端）

- `0x00` u32 = **DDS 偏移 − 4**（`+4` 即 `data.find(b'DDS ')`，两者必须一致，`font_probe` 会校验）
- `0x08` 4B = `'TNFN'`（TT 位图字体魔数）
- `0x30` u32 = **字符数 << 8** → u16 计数实际在 `0x31`（LMSH2: `0xC2400` → 3108）

## 3. 坐标表（rect table）—— 权威几何

- 起点 `0x4F`，条数 = `字符数 − 1`（记 `rectcount`）
- 每条 28B = **7 个大端 float32** `(x, y, w, 0, 0, 0, 0)`
- **记录 i 对应 `gi = i + 1`**（gi 从 1 开始，没有 0）
- `rect_of_gi(g) = 0x4F + 28*(g-1)`；slot3-6 实测全 0（`verify_gi_map.py` 扫过）
- **坐标表才是图集阅读序的权威**；旧脚本按图集行优先顺序推的 k-1/k-3 映射已证伪（见 dead_ends.md）

## 4. 字符表（char table）

- 起点公式：`char_off = 0x4F + 28 * rectcount + 8`，`rectcount = 字符数 − 1`
- 每条 4B = `[cp:u16][gi:u16]` 大端，**按 cp 升序排列**
- 游戏用**二分查找**按 cp 取 gi → 表内重排必须保持 cp 升序，否则"字没了"
- 表长 = `字符数` 条（比坐标表多 1 条；`gi` 最大 3106 = rectcount）

## 5. DDS 图集

- `dds_off = 0x184CF`；**头是 128B 变体**：标准 DDS 偏移被平移，实测 `'NVTT'` 标签在 `+68`，
  fourcc `'DXT5'` 在 `+84`，**像素数据从 `+128` 起**（不要按标准 DDS 的 `+20` 读 fourcc）
- 压缩格式 DXT5 = BC3：每 4×4 块 16B = **BC4 alpha 8B + BC1 rgb 8B**，块按**行优先**排列
- 块地址：`pos = dds_off + 128 + (by * (W/4) + bx) * 16`
- PIL 能直接 `Image.open(BytesIO(data[dds_off:]))` 解码为 RGBA；重编码用 `font_generate.py` 的
  `bc3_encode_batch`（向量化，14 万块约 7 秒）

## 6. 行带几何

- 行带周期 **57px**；行号 `row = rect_y // 57`
- 字形区 `rect_y .. rect_y+47`（48px 高），墨迹 `rect_y+11 .. rect_y+40`
- **基线 = 行带 `y+40`（alpha 墨底）/ `y+39`（白色核心墨底）**，两者差 1px 描边
- 清理槽位时按 `rect_y+1 .. rect_y+49` 的 x 范围（x 范围受邻格保护，见 glyph_model.md）

## 7. 安全边界（最重要 · 决定会不会"字没了"）

**原地等长修改 = 安全**

- 图集像素（重编码被触碰的块）
- rect 的 `w` 浮点值
- 字符表条目里的 **cp 值**
- 字符表**表内重排**（保持 cp 升序）

**禁止（exe 硬编码表偏移，自解析自洽也没用）**

- 插入 / 追加 字符表或坐标表记录
- 加高图集、改计数（`0x31`）
- 实测现象：改完字体能自解析、进游戏"字没了"

**新码位规则**

- 新码位必须 **> 表内最大 cp** 才能接表尾（保持升序）
- 但文本里出现私用区 / 生僻码位（实测 `U+FF61` 半角假名、`U+9FE0` CJK 尾）**启动期闪退**，
  即使字体里有字形 → **新槽位路线整体不可用**，只能原地回收已有槽

## 8. gi 的坑

- `gi` 从 1 开始
- 空格 `U+0020` 与 `U+0091/0092` **共享 `gi=5`** → 回收槽位必须排除共享 gi 的条目
- 两个未使用的 cp 可能共用同一 gi → **按 gi 去重**再算可用槽
- 原版本身就有 2 处共享 gi → "gi 唯一性"的基线不是 0，`font_probe` 会打印基线
- 字体**没有未使用的 gi、图集没有空行带**：所有槽位都被占着，只能靠"部署文本用不到的字"回收
